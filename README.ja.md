# DetailSearch Linker

[English README](README.md)

ノートを書いていると、別のノートの本文に同じ話があるのに、相手のファイル名がそれではないことがある。`認知負荷` という語が研究メモの途中に出てくるだけで、ファイル名は日付付きの日誌、という具合だ。

**DetailSearch Linker** は、いま開いているノートの語句を手がかりに、他ノートの本文を探し、当たった箇所へ見出しリンクを張る Obsidian プラグインである。起動時に Vault 全体を索引しない。コマンドかリボンを押したときだけ動き、ノート内容を外部へ送らない。

挿入するリンクの形は、Obsidian の **ウィキリンクを使用** に従う。オンなら wikilink、オフなら Markdown リンクになる。

## Spot Linker との違い

[Spot Linker](https://github.com/zoupuyo-obsidian/obsidian-spot-linker) と並べて使える。探す対象が違う。

| | Spot Linker | DetailSearch Linker |
|--|-------------|---------------------|
| 探す場所 | **開いているノート**の本文 | **他ノート**の本文 |
| 語句の由来 | ファイル名、title、aliases、任意でタイトルの断片 | 開いているノートから**現在の抽出規則で取り出した語句**、または明示的な**選択コマンド** |
| 一致の意味 | この書き方が、別ノートの名前に見える | この書き方が、別ノートの本文にもある |
| よくできるリンク | そのノートへの `[[ノート名]]` | 当たった段落の近くを指す見出しリンク |
| 無視する語 | 開いているノートで、その書き方を光らせない | **自動抽出**から、その書き方を外す |

概念ごとにノートがあるとき（`認知負荷.md`）は、Spot Linker のほうが向く。本文に同じ語が出たら、そのノートへリンクできる。

相手がノート名ではなく、別ノートの途中の記述であるときは、DetailSearch Linker を使う。研究日誌、引用メモ、会議メモは、ファイル名を概念にしていなくても、同じ語を本文に書いていることがある。

無視する語の一覧はプラグインごとに別である。片方へ足しても、もう片方は変わらない。

## うまくいったときに見えること

1. いまのノートから検索を始める。
2. 他ノートの本文にもある語句が、**いまのノート**で光る。
3. 光った箇所のプレビューを開き、行き先を選んでリンクを作る。
4. その箇所だけが見出しリンクに置き換わる。前後の文はそのまま残る。

光るのは、他ノートの本文に1件以上当たった語句だけである。1件も当たらない語は飾らない。

## 導入

Obsidian **1.13.0** 以降が必要である。デスクトップでもモバイルでも動く。

### コミュニティプラグインから

コミュニティディレクトリへ登録されたあとは、次の手順で導入できる。

1. **設定 -> コミュニティプラグイン** を開く。
2. 必要なら Restricted mode をオフにする。
3. 一覧で **DetailSearch Linker** を探してインストールする。
4. プラグインを有効にする。

### GitHub リリースから

1. [GitHub Releases](https://github.com/zoupuyo-obsidian/obsidian-detailsearch-linker/releases) から最新の `main.js`、`manifest.json`、`styles.css` を取る。
2. Vault に `.obsidian/plugins/detailsearch-linker/` を作る。
3. 3つのファイルをそのフォルダへ置く。
4. **設定 -> コミュニティプラグイン** で DetailSearch Linker を有効にする。

## 基本操作

いちばん使うのは **DSL: 本文候補を検索** である。リボンの検索アイコンも同じ自動抽出を行う。どちらも残っている文字選択を無視し、クリップボードを読むことはない。デスクトップでは、隣の選択アイコンが **DSL: 選択語を検索** と同じ動作をする。`DSL` は DetailSearch Linker を表す短縮表記である。

### iPhoneで任意の語句を検索する

iPhoneでは、下部のコマンドメニューに次の2つを登録して使う。

- **DSL: 本文候補を検索**：選択状態やクリップボードを使わず、現在ノートから候補語を自動抽出する。
- **DSL: コピー語を検索**：本文の任意の語句をコピーしてから実行し、コピーした語句そのものを他ノート本文から探す。同じいま開いているノートで同じコピー語をもう一度実行すると、そのコピー語の強調を消す。もう一度押すと再検索する。

明示的なコピー語検索では「選択 → コピー → コピー語を検索」の順に操作する。コピー後も選択が残っている場合は、プラグインがコピー内容を読み取ってから選択を自動で解除する。同じ語がノート内に複数あるときは、解除前の選択位置を使って対象箇所を決める。すでに選択が外れていれば、カーソルに最も近い同じ語を使う。

### 正式公開前のiPhoneテスト（BRAT）

正式版とは別のDevプラグインは使わない。テスト版も **DetailSearch Linker** として、BRATから同じリポジトリを追加する。

1. 正式版の DetailSearch Linker を無効にする。
2. コマンドパレットで **BRAT: Add a beta plugin for testing** を実行する。
3. `zoupuyo-obsidian/obsidian-detailsearch-linker` を入力する。
4. beta版を有効にして、表示・全体検索・コピー語検索を確認する。
5. テスト後はBRATのbetaプラグイン一覧から削除し、正式版を有効に戻す。

beta版は正式版と同じプラグインIDを使うため、両方を同時に有効にはしない。

### 選択を明示して探す

1. ノートを開き、リンクにしたい語句を選ぶ。例は `認知負荷` である。
2. **DSL: 選択語を検索** を実行する。デスクトップではリボンの選択アイコンでもよい。**DSL: 本文候補を検索** とリボンの検索アイコンは選択を無視して自動抽出する。
3. プラグインは、その語句だけを**他ノートの本文**から探す。いまのノートから別の語は取り出さない。
4. いま選択した箇所だけが光る。既存のリンク、コード、数式、frontmatter の中は対象外である。同じ語句の別の箇所は、このコマンドでは光らない。
5. デスクトップでは光った箇所へマウスを乗せる。モバイルではタップする。プレビューに、行き先ノート、いちばん近い見出し、短い抜粋が出る。
6. 欲しい行き先の **リンクを作成** を押す。その箇所が見出しリンクになる。

選択して探した場合、その語句が「無視する語」に入っていても検索する。すでに書き方が決まっていて、他ノートの本文に同じ語があるかだけ見たいときに使う。

選択が、既存リンクやコードなど保護された範囲と重なっていると、他ノートを読む前に止まる。いまのノートの地の文に、その語句が残っている必要がある。

### 本文候補を探す（自動抽出）

1. ノートを開く。残っている文字選択は無視され、クリップボードは読まれない。
2. **DSL: 本文候補を検索** を実行するか、リボンを押す。
3. プラグインは現在の抽出規則を使う。見出し、太字、ハイライトに加え、設定によっては地の文や n-gram からも候補語を取る。
4. 取り出した語句を、他ノートの本文から探す。
5. 他ノートに当たった語句だけが光る。光った箇所は、**その語句だけ**に属する。
6. プレビューを開くと、その語句の行き先だけが見える。取り出した語が全部混ざることはない。
7. **リンクを作成** で、その箇所を置き換える。

自動抽出は入力欄を出さず、考えられる語句をすべて拾うものでもない。明示的に探したい語句には、**DSL: 選択語を検索** または **DSL: コピー語を検索** を使う。

### リボンと主コマンド

| いまの状態 | リボンの検索アイコン | **DSL: 本文候補を検索** |
|-----------|----------------------|--------------------------------------|
| 強調がない（選択は残っていてよい） | 自動抽出する。選択は無視する | 自動抽出する。選択は無視する |
| いま開いているノートに強調がある | 先に強調を**消す** | 先に強調を**消す** |
| そのあと次に押す | 自動抽出する | 自動抽出する |

リボンと **DSL: 本文候補を検索** は、同じ本文候補の検索を行う。いま開いているノートに結果があるときは、最初の押下で強調を消し、その次の押下で自動抽出を始める。

強調は、いつでも **DSL: 強調を消す** またはステータスバーの表示で消せる。主コマンドとリボンも、いま開いているノートに結果があるときは最初の押下で強調を消す。

### プレビューが開いたあと

**リンクを作成**は、光っている箇所へ見出しリンクを入れる。行き先ノートで、当たった位置より前に見出しが無ければ、ノートそのものを指す。

**ノートを開く**は、行き先を読むための操作である。元のノートへ戻っても、強調は残る。

**この語を無視**は、次の節で述べる。**強調を消す**は、いま見えている結果一式を終わらせる。

デスクトップでは、プレビューが出た時点でキーボード操作の対象がそちらへ移る。Tab と矢印キーは、その枠の中を動く。光った箇所からマウスを外すか Escape を押すと、ノート本文へ戻る。

プレビューをクリックしたあとは、Escape か本文クリックまで開いたままである。

### キーボード

編集中の `Tab` と `Enter` は、いつもどおり文字入力と改行に使う。マウス無しで強調を渡り歩くには、次のコマンドへホットキーを付ける。

- **次の強調へ移動**
- **前の強調へ移動**
- **カーソル位置のリンク候補を開く**

「候補ノート数バッジ」を消していても、これらのコマンドは使える。既定のホットキーは無い。

### 以前のコマンド

**DSL: 選択語を検索**は、明示的な選択用コマンドである。何も選んでいないと入力欄が開く。打ち込んだ語句は、いまのノートに存在する必要があり、明示検索で光るのは選択した箇所、または入力した語句に対応する1箇所だけである。

**DSL: 自動抽出して検索**は、診断用のコマンドである。残っている選択や現在の強調に関係なく、自動抽出を強制する。

日常の操作は **DSL: 本文候補を検索** とリボンで足りる。明示検索と診断用のコマンドも残してある。

### モバイル

Obsidian の **モバイルツールバー** へ **DSL: 本文候補を検索** を足す。リボンが出る環境では、上の表と同じ動作になる。光った箇所をタップするとプレビューが開く。

## 無視する語と停止語

語句を隠す一覧は2つある。同じものではない。

**無視する語**は、自分で外した語句である。効くのは自動抽出だけであり、次の自動抽出では探さない。同じ語句を選んで明示的に探せば、また使える。

**停止語**は、取り出しのときに除く一般語である。英語なら `the` や `and`、日本語なら `の` や `は` がこれに当たる。自動抽出の雑音を減らすための一覧であり、選択して探した場合は止まらない。

プレビューの **この語を無視** は、語句の前後の空白を除いて **無視する語** へ足し、いまのノートから、その語句の強調だけを消す。ほかの語句の強調は残る。

設定画面から語を消しても、開いているノートをすぐ再検索はしない。次の自動抽出から、また候補になり得る。

## 設定を変えると何が変わるか

設定は3つに分かれる。**どの他ノートを読むか**、**いまのノートからどの語句を取るか**、**結果の見え方**である。

対象フォルダと検索範囲は、いまのノートから取り出す語句を変えない。変わるのは、行き先になり得る他ノートだけである。いまのノートは、どこに置いてあっても抽出の対象になる。

### どのノートを探すか

- **対象フォルダ**：1行に1フォルダ。空欄なら、除外フォルダ以外の Vault 全体である。ここに無いノートは、行き先にならない。
- **除外フォルダ**：ここにあるノートは読まない。テンプレート、添付、取り込み直後の置き場に使う。
- **検索範囲**：**対象フォルダ全体**、**最近更新したノート**、**作業集合（最近開いたノート）**、**最近更新 + 作業集合**。範囲を狭めると早く終わる。古いノートは外れやすい。
- **最近更新（日数）**：最近更新系の範囲で使う。`0` なら、その範囲の中で日数制限は無い。
- **作業集合サイズ**：最近開いたノートを何件まで覚えるか。`0` なら上限は無い。
- **最大走査ファイル数**：1回の実行で読むノート数の上限である。超えた分は後回しにせず、読まない。既定は 500 件である。
- **最大ファイルサイズ**：これより大きいノートは飛ばす。既定は 512 KB である。

### どの語句を取り出すか（自動抽出だけ）

選択して探した場合、この節の設定は使わない。選んだ語句そのものを探す。

- **見出し・強調を優先抽出**：オン（既定）なら、`#` 見出し、太字、`==ハイライト==` から語句を取る。オフなら、これらの由来は使わない。
- **通常本文から語句抽出**：オン（既定）なら、地の文から単語と複数語句を偏らないように取る。同じ語が何度も出る場合は優先度が上がる。オフなら、見出しと強調だけ（それらがオンのとき）になる。
- **広域 n-gram 抽出**：オフ（既定）のままが無難である。オンにすると、空白で切れない日本語などの連続部分から、決めた長さの断片をずらして切り出す。候補は増える一方、たまたま同じ数文字が別ノートにあるだけの弱い一致も増えやすい。
- **最小語長 / 最大語長**：この範囲の外の語句は捨てる。最小を上げると、助詞や2文字の断片が減る。
- **n-gram 最小長 / 最大長 / 1 span の n-gram 上限**：広域 n-gram がオンのときだけ使う。幅を広げると、同じ連続部分から切り出す断片が増える。
- **自動候補数の基準**：既定は 40 件。自動調整では内部で既定 120 語（基準値を上げた場合は最大 200 語）を一括探索し、ヒット後に本文内の強調密度を見て、おおむね 20〜60 語を表示する。固定上限モードでは、この値が表示上限になる。
- **候補数の調整方法**：既定の「自動調整」は、候補ノート数ではなく、現在ノートで光る箇所数を基準にする。多くの候補があっても本文が過密になりにくい。必要なら固定上限へ切り替えられる。
- **手動辞書語**：1行1語。登録した語は優先して候補にし、より長い複合語の中でも見つける。
- **リンク作成から語を学習**：リンクを実際に作成した安全な語だけを、この Vault の設定内へ記録する。検索しただけでは学習しない。学習済み辞書語は編集・削除・一括消去でき、最大200語である。
- **停止語**：取り出しのときに除く。
- **無視する語**：取り出しのときに除く。選択して探す操作は止まらない。
- **大文字と小文字を区別**：オフ（既定）なら、英語は大小を無視する。日本語への影響はほとんど無い。

取り出した語句が多すぎるときは、太字とハイライト、見出し、地の文、n-gram の順で優先する。地の文では、繰り返し出る語を優先する。

### 結果の見え方と件数

- **光らせ方**：いまのノートでの見え方である。反転、マーカー、文字色、下線から選ぶ。
- **候補ノート数バッジ**：その語句の行き先が何ノートあるかを出す。キーボード操作だけ使うなら消してよい。
- **ノート切替で強調を消す**：オン（既定）なら、別ノートを開いたときに飾りを消す。オフなら、そのノートを再び開いたときまで残る。**ノートを開く**で行き先を見に行った場合は、元の強調は残る。
- **抜粋の文字数**：プレビューに出す行き先本文の長さである。ディスク上のキャッシュには残さない。
- **1ノートあたりの最大一致数**：1つの行き先ノートの中で、何件まで取るかである。ノート自体は残る。同じファイルの後ろの一致は落ちる。
- **最大候補ノート数**：1つの語句が集められる行き先ノートの上限である。
- **キャッシュ**：**上限付き永続**（既定）は、検索語、パス、見出し、位置、更新時刻を `data.json` に覚え、同じ語の再検索で未変更ファイルを飛ばせる。**メモリのみ**は、Obsidian を閉じると忘れる。抜粋とノート全文はディスクへ書かない。
- **キャッシュ上限 (MB)**：超えたときは、古い検索語から消す。
- **UI 言語**：プラグイン画面の言語だけである。

## 設定例

### 日本語の概念ノートを、控えめにつなぐ

いまのノートが文章で、行き先にしたいのがデイリーではなく、まとまったノートであるときの例である。

- できあがったノートが入っているフォルダだけを対象にする。
- デイリー、テンプレート、取り込み置き場は除外する。
- **見出し・強調を優先抽出** と **通常本文から語句抽出** はオンのままにする。
- **広域 n-gram 抽出** はオフのままにする。
- **最小語長** は 3 のままにする。
- **無視する語** は、同じ誤検出が繰り返されるまで空でよい。

文字選択が残っていても **DSL: 本文候補を検索** を実行する。光った箇所の抜粋を読んでからリンクを作る。自動抽出では、末尾が `の`、`を`、`し` などの不自然な境界になる候補を除く。それ以外の短い誤候補が繰り返し光る場合は、最小語長を上げるか、その断片を **無視する語** へ足す。

### 選んでから探す下書き

探したい語句が自分で分かっていて、プラグインに推測させたくないときの例である。

- 自動抽出の設定は、既定のままでよい。
- 語句を選んでから、**DSL: 選択語を検索** を実行する。デスクトップではリボンの選択アイコンでもよい。主コマンドやリボンの検索アイコンを押すと、選択が残っていても自動抽出になる。
- `API` と `api` を分けたいとき以外は、**大文字と小文字を区別** をオフのままにする。

まだ印を付けていないノートでは、自動抽出を予備として使える。「無視する語」は、この明示的な検索を止めない。

### 最近の研究と会議メモ

行き先として役に立つのは、今月触ったノートだ、というときの例である。

- **検索範囲** を **最近更新したノート**、または **最近更新 + 作業集合** にする。
- **最近更新（日数）** は、既定の 30 のままでよい。Vault が忙しいなら 14 にする。
- 研究や案件のフォルダを対象にする。
- よく使う語の行き先が途中で切れるときだけ、**最大候補ノート数** を上げる。

**対象フォルダ全体** にすると、古い文章も当たる。各語句の初回は、その分時間がかかる。

### 大きくて用途が混ざった Vault

**対象フォルダ** が空だと、除外以外のノートを、**最大走査ファイル数**（既定 500）まで読む。広い自動抽出の前に、フォルダを決めておく。

- 行き先にしたいフォルダだけを **対象フォルダ** へ書く。
- アーカイブ、OCR の置き場、自動生成のファイルは **除外フォルダ** へ書く。
- **最大走査ファイル数** は、負荷が分かるまで 200 から 500 のあいだに置く。
- **広域 n-gram 抽出** はオフのままにする。
- 検索語の履歴を `data.json` に残したくなければ、キャッシュを **メモリのみ** にする。

実行後に省略の通知が出たら、サイズ上限か件数上限に当たっている。そのノートは読んでいない。

### 自動抽出がうるさいとき

一度自動抽出したあと、リンクしない語ばかり光るときの手順である。

1. 不要な強調のプレビューを開き、**この語を無視** を押す。
2. 英語の一般語が候補として残り続けるなら、**停止語** へ足す。
3. **通常本文から語句抽出** をオフにし、見出しと強調だけにする。
4. 短い日本語の断片が残るなら、**最小語長** を 4 にする。

無視した語の強調は、その場で消える。ほかの語句は残る。次の自動抽出では、無視した語は戻ってこない。

## 保護範囲と、受け付けない検索語

既存の Markdown リンク、wikilink、コード、数式、frontmatter の中は、探しも取り出しもしない。選択がこれらの範囲と重なると、通知を出して止まる。

検索語に `|`、`[`、`]` は使えない。`、` のような普通の日本語の句読点は使える。

作るリンクは見出しリンクだけである。行き先ノートへ block ID は書き込まない。

1回の実行が、すべてのノートを見る保証は無い。フォルダ、範囲、件数、サイズの上限で、読まないファイルが出る。上限を外した無制限の取り出しは無い。

## プライバシー

読み取りとキャッシュは、使っている端末の中で完結する。既定の永続キャッシュは、検索語と、当たったパス、見出し、位置、更新時刻を、設定と同じプラグインの `data.json` へ書く。抜粋とノート全文は残さない。

辞書の手動語と学習語も同じ Vault のプラグイン設定にだけ保存する。外部サービスへの送信や、他Vaultとの共有は行わない。

これらの情報をディスクに置きたくなければ、**メモリのみ** にするか、**検索キャッシュを消去** する。

## 開発

手順は [CONTRIBUTING.md](CONTRIBUTING.md) にある。

```bash
npm install
npm test
npm run build
npm run lint
```

開発版を差し替えたあと（Vault のジャンクションやシンボリックリンクでも）は、プラグインを一度オフにしてからオンにするか、Obsidian を再読み込みする。読み込み済みの `main.js` はメモリに残る。

`npm run verify:release` は版情報を確認し、`main.js`、`manifest.json`、`styles.css` の `SHA256SUMS` を書き出す。
