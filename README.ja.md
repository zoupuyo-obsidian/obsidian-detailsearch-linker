# DetailSearch Linker

[English README](README.md)

DetailSearch Linker は、**現在ノート** から自動抽出または選択した語句を **他ノート本文からオンデマンド検索** し、**現在ノート** 内の anchor を強調表示したうえで、プレビュー確認後に `[[path#heading|表示]]` 形式の wikilink を挿入するプラグインです。

**全文索引ではありません。** 起動時に Vault 全体を走査しません。ノート内容が外部送信されることもありません。

## 機能

### 選択語検索（第2案）

- **選択語の本文検索** — 語句を選択してコマンド実行。未選択時は入力モーダル。
- **Spot Linker 風の強調** — 現在ノート内の検索語を装飾し、候補ノート数バッジを表示可能。
- **見出し付き wikilink** — `[[linktext#heading|元の表示]]` を挿入。

### 自動抽出（第1案）

- **現在ノートから本文リンク候補を探す** — 見出し・太字・ハイライト、および任意で通常本文・広域 n-gram から候補語を抽出。
- **保守的な既定値** — focused ON、broad n-gram OFF、停止語、語長制限、ハードキャップ 200。優先度: 強調/ハイライト(1200) > 見出し(1000) > 本文句(400+長) > n-gram(100+長)。
- **一致 0 の語は強調しない** — 他ノートにヒットした語だけ装飾。

### 統合セッション（第3案）

- **語句ごとの結果グループ** — anchor ごとに query グループを保持。popover とリンク作成はそのグループのみ使用。
- **複数語 1 読み** — 対象ファイルは最大 1 回 `cachedRead`、Aho–Corasick で複数パターンを一括照合。
- **term 単位キャッシュ** — warm な term は再読 0。キャンセル時は不完全走査を complete 扱いしない。

共通: 検索範囲、クエリキャッシュ、進捗・中止、世代ベース無効化。

## インストール

### 手動インストール

1. `main.js` / `manifest.json` / `styles.css` をビルドまたは入手。
2. Vault 内に `.obsidian/plugins/detailsearch-linker/` を作成。
3. 3 ファイルを配置。
4. **設定 → コミュニティプラグイン** で DetailSearch Linker を有効化。

Obsidian **1.13.0** 以降（デスクトップ・モバイル）。

## 使い方

### 統合操作（推奨）

1. ノートを開く。
2. **現在ノートの本文リンク候補を探す** を実行（コマンドパレット、リボン、モバイルツールバー）。
3. **選択あり** — 選択語を他ノート本文から検索（選択モードと同じ）。
4. **選択なし** — 現在ノートから候補語を自動抽出（入力モーダルは出しません）。
5. 強調箇所をホバー / タップして候補を確認し **リンクを作成**。

リボンも同じ分岐です: 選択あり → 検索（強調があっても再検索）／選択なし＋強調あり → 解除／選択なし＋強調なし → 自動抽出。

後方互換・診断用に **選択語を他ノート本文から探す** と **現在ノートから本文リンク候補を探す** も残しています。

### 選択モード（従来コマンド）

1. ノートを開き、語句を選択（空でも可）。
2. **選択語を他ノート本文から探す** を実行。リボンは統合操作を呼びます。
3. 強調箇所をホバー / タップして候補を確認し **リンクを作成**。

未選択時はこの従来コマンドのみ入力モーダルを出します。統合コマンドでは出しません。

### 自動抽出モード（従来コマンド）

1. ノートを開く（選択不要）。
2. **現在ノートから本文リンク候補を探す** を実行。
3. ヒットのある語だけ強調。anchor ごとにその語の候補数バッジ。
4. 各 anchor の popover には **その語の候補のみ** 表示。

リボン（選択なし時）、ステータスバー、**強調を消す** で解除。**検索を中止** で走査中断。

### 無視リスト（Spot Linker 風）

- **無視する語** は **自動抽出のみ** に適用。選択語の明示検索（無視した語を再選択して検索）も常に可能。
- プレビュー popover の **この語を無視** で、trim した語を設定の無視リストへ追加し、その語の強調だけ現在セッションから削除。他の語の highlight は維持。
- **停止語** は抽出の一般語調整、**無視する語** はユーザーが候補から外した語。
- 設定から語を削除しても、実行中セッションの即時再検索は行いません。次の自動抽出から再び候補になり得ます。

### モバイル

- **リボン**（検索アイコン）は `addRibbonIcon` で表示され、上記の統合操作と同じです。
- Obsidian 標準の **モバイルツールバー** 設定から **現在ノートの本文リンク候補を探す** を追加できます。プラグイン側から下部配置を強制しません。

### 未選択時（選択コマンドのみ + モーダル）

選択が空のときはモーダルで検索語を入力します。**現在ノート内（保護範囲外）に同語がなければ Notice を出して中止**し、他ノートは走査しません。

### 検索語と wikilink 構文

検索語に `|`, `[`, `]` は使えません（wikilink を壊すため）。`、` など通常の日本語句読点は可。リンク先見出しに `|` が含まれる場合は escape せず、表示が崩れることがあります（既知の制限）。

## 設定の要点

| 設定 | 用途 |
|------|------|
| 見出し・強調を優先抽出 / 通常本文 / 広域 n-gram | 自動抽出のソース |
| 最小・最大語長、最大自動候補数、停止語 | 抽出の調整 |
| 無視する語 | 自動抽出用のユーザーブロックリスト（選択検索は影響なし） |
| 対象 / 除外フォルダ、検索範囲 | 走査ノートの限定 |
| キャッシュ / 上限 MB | メモリのみ vs 永続 LRU（既定は永続） |
| 1ノート最大一致 / 最大候補ノート | 結果爆発の抑制 |

## Cold / Warm 検索

- **Cold** — `vault.cachedRead`、約 64KiB チャンク + UI yield。
- **Warm** — term 単位キャッシュ。未変更ファイルは再読込しない。
- **複数語** — 1 ファイル 1 読み、必要な term をまとめて照合。

## 制限事項

- **網羅性なし** — フォルダ・範囲・件数・サイズ上限で見落とし得る。
- **起動時索引なし** — 語数と範囲に比例したコスト。
- **見出しリンクのみ** — block ID は書き込まない。
- **保護範囲** — 既存リンク・コード・数式・frontmatter 内は除外。**保護範囲と重なる選択は検索前に中止**。
- **検索語の link 構文** — クエリの `|`, `[`, `]` は拒否。リンク先見出しの `|` は非 escape（既知の制限）。
- **広域 n-gram は opt-in** — 誤検出が増えやすい。無制限モードはなし。

## プライバシー

読み取り・キャッシュはすべてローカルで、外部送信しません。既定の **永続**
キャッシュでは、検索語と一致した path・見出し・位置・抜粋・mtime を設定とともに
プラグインの `data.json` へ保存します。ノート全文の本文は保存しません。検索情報を
ディスクへ残したくない場合はメモリのみを選ぶか、検索キャッシュを消去してください。

[CONTRIBUTING.md](CONTRIBUTING.md) を参照。

```bash
npm install
npm test
npm run build
npm run lint
```

開発版を更新したあと（Vault ジャンクション / シンボリックリンクでも）は、**プラグインを一度 OFF → ON** するか **Obsidian を再読み込み** してください。ロード済みの `main.js` はメモリに残り、ディスク上のファイル差し替えだけでは反映されません。
